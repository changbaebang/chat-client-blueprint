# 13. 예외 상황

| 항목 | 값 |
| ---- | -- |
| 브랜치 | `stage/13-error-states` |
| 선행 | 11 (12는 선택) |
| 읽을 문서 | [DESIGN 3.3절 상태별 화면](../docs/DESIGN.md#33-상태별-화면), [4.7절](../docs/DESIGN.md#47-오류-코드), [7.2절](../docs/DESIGN.md#72-전송과-중단), [9.11절의 STATE-6](../docs/DESIGN.md#911-srcstate), [11.2절](../docs/DESIGN.md#112-작성-규칙), [12장](../docs/DESIGN.md#12-운영과-관측) |
| 고칠 폴더 | `src/state`, `components` |
| 쓸 스킬 | (설치하면) `e2e-test-design`, `critical-review` |

## 이 단계가 끝나면

- [ ] DESIGN 3.3절 표의 행마다 e2e가 있다.
- [ ] 목록의 다음 페이지가 실패해도 요청이 반복되지 않는다. 서버를 막은 채 요청 수를 센다.
- [ ] 답변 도중 연결이 끊겨도 받은 글을 잃지 않는다. 10단계의 모듈 테스트(`api/responses`, `state/chats`)가 이 경로를 본다.
- [ ] 화면 하나가 던지면 그 화면만 오류 경계가 잡고 사이드바는 남는다.
- [ ] 오류 안내에 요청 ID가 보인다.
- [ ] 오류 종류와 화면 문구가 나뉘어 있다(STATE-6).

## 순서

1. **입력** 프롬프트 1.
2. **확인**

   ```powershell
   bun run check
   bun --bun playwright test --grep @errors
   ```

3. **직접 확인** `bun run dev`로 앱을 열어 둔 채 그 터미널에서 Ctrl+C로 개발 서버를 끈다. 웹과 API가 함께 꺼지지만 열린 페이지는 남는다. 그 페이지에서 채팅을 열고 보내 본다. 무엇이 보이는지 적는다. 서버를 다시 켜고 Retry가 되는지 본다.
4. **검토 지점** 오류 종류를 고르는 곳(state)과 문구를 고르는 곳(components)을 읽는다. 같은 404가 채팅 열기에서는 "찾을 수 없음"이고 삭제에서는 성공인 것이 코드에서 어디로 갈리는지 짚는다.
5. **입력** 검토 프롬프트. 절은 "3.3절, 4.7절, 7.2절, 9.11절, 12장".
6. **입력** 반영 프롬프트.

## 프롬프트 1. 구현

```text
이 저장소는 docs/DESIGN.md의 채팅 앱이다. 먼저 AGENTS.md와 docs/TASKS.md의 지금 상태를 읽고 AGENTS.md의 규칙을 따른다.
고칠 폴더에 POLICY.md가 있으면 먼저 읽는다. "승인"인 정책만 규칙이다.
DESIGN.md나 승인된 정책과 부딪히거나, 되돌리기 어렵거나 다른 단계에 걸리는 판단이 필요하면 고치기 전에 멈추고 규칙 ID, 이유, 권장안을 보고한다. 그 밖의 작은 판단은 정한 뒤 보고의 "정한 것"에 적는다.
테스트를 먼저 쓰고, 구현하기 전에 돌려서 실패하는 출력을 보인다. 그 실패가 고칠 결함 때문인지도 본다.
테스트의 전체 출력은 시각을 붙인 로그 파일로 보내고, 대화에는 마지막 요약과 실패만 보인다.
끝나면 AGENTS.md 12장의 형식으로 보고한다. 돌리지 않은 것과 확인하지 못한 것은 그렇다고 쓴다.

이번 단계: 13 예외 상황. 브랜치 stage/13-error-states 를 main에서 만든다.
DESIGN 3.3절, 4.7절, 7.2절, 9.11절, 11.2절, 12장을 읽는다. 이 단계의 e2e 에는 @errors 태그를 단다.

1. 테스트 먼저(e2e, asUser fixture). DESIGN 3.3절의 표를 한 행씩 테스트로 옮긴다.
   - 목록 첫 읽기 중 스켈레톤, 빈 목록 문구.
   - 다음 페이지 실패: page.route 로 실패시키고 3초 동안 요청 수를 세어 1이다. Retry 를 누르면 다시 읽는다.
   - 채팅 읽기 실패: Try again 이 보이고 누르면 다시 읽는다. 404 면 찾을 수 없음 화면이다.
   - 열기 전 실패: [[mock:slow]] 답변 중에 다른 탭(같은 컨텍스트의 새 page)에서 같은 채팅에 보내면 409 다.
     임시 메시지가 빠지고 쓴 글이 입력창에 돌아오고 이유가 보인다. 413 과 네트워크 실패(page.route abort)도 같다.
   - 화면 하나가 던짐: 렌더 중 던지게 하는 방법이 앱 코드에 없어야 한다. page.route 로 메시지 응답을 계약에 안 맞는 모양으로 바꿔
     채팅 화면이 던지게 하고, 그 화면만 "Something went wrong" 과 Reload 이고 사이드바가 남는지 본다.
     다른 채팅이나 화면으로 가면 오류 경계가 풀린다. 다시 시도는 그 화면만 다시 그린다.
   - 401: 저장된 사용자 id를 없는 id로 바꾸고 이름을 바꾸면 고르기 화면이고 next 가 그 채팅이다. 다시 고른 뒤에도 쓰던 초안이 남아 있다.
   - 요청 ID: 오류 안내에 "Reference:" 와 응답의 X-Request-Id 값이 보인다.
   - 토스트: 이름 변경, 고정, 삭제의 실패가 토스트로 보인다.
   돌려서 실패하는 출력을 보인다.
2. 구현
   - state: 오류를 종류로 나눈다. 예: network, not_found, conflict, too_large, user_required, unknown. ApiError 의 status 와 code 에서 고른다.
     요청 ID 를 오류에 담는다. 문구는 components 에서 정한다(STATE-6).
   - 목록의 다음 페이지는 실패하면 멈추고 자동으로 다시 읽지 않는다.
   - components: 스켈레톤과 빈 화면, 채팅 오류 화면, composer-notice 의 이유 문구, screen-boundary(라우팅된 화면만 감싼다), 요청 ID 표시.
   - 끊김은 10단계의 syncWithServer 경로를 쓴다. 새 경로를 만들지 않는다.
3. 확인: bun run check, bun --bun playwright test --grep @errors 를 세 엔진에서, bun run test:e2e.
4. 작게 커밋한다.
```

## 화면 점검

기능의 확인이 끝난 뒤, 검토 프롬프트 전에 한다. 틀은 [README 6.12절](README.md#612-화면-점검), 기준은 [DESIGN 3.7절](../docs/DESIGN.md#37-화면-품질)이다.

```text
이 단계의 화면 점검을 한다. 기준은 docs/DESIGN.md 3.7절이다. 앱 코드는 고치지 않는다.
1. SCREENS_STAGE=13 bun run test:screens 를 돌려 docs/evidence/ui/13/ 에 캡처를 남긴다.
   이 단계에서 생긴 화면과 상태가 @screens 에 없으면 먼저 더한다.
2. 처음 쓰는 사람의 눈으로 흐름을 따라간다: 목록과 채팅의 로딩, 빈 화면, 읽기 실패와 Try again, 전송 실패, 답변 중 끊김, 오류 경계, 사용자를 모를 때(401).
   밝은 테마와 어두운 테마, 창 1280x800, 1024x700, 1280x480.
3. docs/evidence/ui/13/CHECK.md 를 만든다. UX-1부터 UX-10까지 행마다 캡처 파일, 본 것,
   판정(맞음, 고칠 것, 사람이 볼 것)을 쓰고, 끝에 사람이 체크할 빈 칸을 둔다.
4. 같은 상황의 안내 문구를 표로 모은다(UX-7).
5. 일반 AI 에이전트 웹앱과 다르게 한 곳은 docs/evidence/ui/compare.md 에 이유와 함께 적는다(UX-2).
   일반 AI 에이전트 웹앱의 화면은 사람이 직접 찍어 docs/evidence/ui/reference/ 에 넣은 것만 쓴다.
6. "고칠 것"을 목록으로 보이고 멈춘다. 이 단계에서 고칠지 15단계로 넘길지는 내가 정한다.
```

**사람** 캡처를 열어 보고 `CHECK.md`의 빈 칸에 체크한다. 캡처로 모자라면 앱을 띄워 위 흐름을 직접 써 본다. 체크하지 않은 단계는 반영하지 않는다(UX-10).

## 막히면

- **오류 경계가 사이드바까지 지운다.** 경계가 셸 전체를 감싸고 있다. 라우팅된 화면만 감싼다.
