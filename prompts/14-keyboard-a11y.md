| 항목 | 값 |
| ---- | -- |

| 읽을 문서 | [DESIGN 3.4절 단축키](../docs/DESIGN.md#34-단축키), [3.5절 접근성](../docs/DESIGN.md#35-접근성), [7.3절](../docs/DESIGN.md#73-브라우저-규칙), [9.12절의 COMP-7](../docs/DESIGN.md#912-srccomponents), [9.13절의 STYLE-7](../docs/DESIGN.md#913-srcstyles) |

## 이 단계가 끝나면

- [ ] 단축키 목록이 `shell/shortcuts.ts` 하나에 있고, 처리, 사이드바 툴팁, `mod+/` 도움말이 모두 그것을 읽는다.
- [ ] 다이얼로그나 메뉴가 열려 있으면 단축키가 실행되지 않고, 브라우저의 기본 동작도 막힌다. 누르고 있어도 한 번만 실행된다.
- [ ] 열고 닫는 모든 UI가 닫힐 때 연 곳으로, 그곳이 사라졌으면 화면의 `h1`로 포커스를 돌려준다.
- [ ] 키보드만으로 사용자 고르기부터 보내기, 멈추기, 이름 변경, 고정, 삭제, 사용자 바꾸기까지 할 수 있다.
- [ ] 실제 화면(홈, 채팅, 사용자 고르기)에서 두 테마의 대비를 재고, 가장 낮은 값이 기준을 넘는다.
- [ ] 동작 줄이기에서 앱의 모든 반복 애니메이션이 멈춘다.

## 순서

1. **입력** 프롬프트 1.
2. **확인**

   ```powershell
   bun run check
   bun --bun playwright test --grep @a11y
   ```

3. **직접 확인**
   - 마우스를 쓰지 않고, 프롬프트 1의 "키보드만으로" 시나리오를 손으로 한 번 해 본다. 포커스가 보이지 않거나 길을 잃는 곳을 적는다.
   - Windows의 내레이터(Ctrl+Win+Enter)를 켜고 답변을 하나 받는다. 끝날 때 한 번 읽히는지 본다. 끝나면 끈다.
   - 실제 Chrome에서 `Ctrl+Shift+O`가 북마크 관리자가 아니라 앱의 새 채팅으로 가는지 본다. 버전은 `chrome://version` 첫 줄의 숫자를 적는다. 사람이 확인한 뒤에만 "확인했다"로 쓴다(DESIGN 11.6절).
4. **검토 지점** `shell/shortcuts.ts`와 단축키 처리기를 읽는다. 열린 다이얼로그와 메뉴를 묻는 곳이 하나인지(COMP-5) 본다.
5. **입력** 검토 프롬프트. 절은 "3.4절, 3.5절, 7.3절, 9.12절, 9.13절".
6. **입력** 반영 프롬프트.

## 프롬프트 1. 구현

```text
이 저장소는 docs/DESIGN.md의 채팅 앱이다. 먼저 AGENTS.md와 docs/TASKS.md의 지금 상태를 읽고 AGENTS.md의 규칙을 따른다.
고칠 폴더에 POLICY.md가 있으면 먼저 읽는다. "승인"인 정책만 규칙이다.
DESIGN.md나 승인된 정책과 부딪히거나, 되돌리기 어렵거나 다른 단계에 걸리는 판단이 필요하면 고치기 전에 멈추고 규칙 ID, 이유, 권장안을 보고한다. 그 밖의 작은 판단은 정한 뒤 보고의 "정한 것"에 적는다.
테스트를 먼저 쓰고, 구현하기 전에 돌려서 실패하는 출력을 보인다. 그 실패가 고칠 결함 때문인지도 본다.
테스트의 전체 출력은 시각을 붙인 로그 파일로 보내고, 대화에는 마지막 요약과 실패만 보인다.
끝나면 AGENTS.md 12장의 형식으로 보고한다. 돌리지 않은 것과 확인하지 못한 것은 그렇다고 쓴다.

이번 단계: 14 단축키와 접근성. 브랜치 stage/14-keyboard-a11y 를 main에서 만든다.
DESIGN 3.4절, 3.5절, 7.3절, 9.12절, 9.13절을 읽는다. 이 단계의 e2e 에는 @a11y 태그를 단다.

1. 테스트 먼저(e2e, asUser fixture)
   - 단축키: 3.4절의 표마다. 한글 자판을 흉내 내(key 가 한글, code 가 KeyO) mod+Shift+O 가 동작한다.
     키를 누르고 있으면(repeat) 한 번만 동작한다. 메뉴나 다이얼로그가 열려 있으면 동작하지 않고 defaultPrevented 다.
     mod+/ 가 도움말을 열고, 도움말의 목록이 사이드바 툴팁의 단축키 표기와 같다.
     / 는 Shift 와 함께 눌러도 받는다. AltGr(Ctrl+Alt)는 단축키가 아니다.
   - 포커스: 행 메뉴, 헤더 메뉴, 삭제 확인, 이름 변경 입력, 도움말을 열고 닫을 때마다 연 곳으로 돌아온다.
     보고 있던 채팅을 지워 연 곳이 사라지면 홈의 h1 로 간다(COMP-7).
     Pin 과 Unpin 처럼 아무것도 열지 않는 메뉴 항목 뒤에는 메뉴 버튼으로 간다(행이 옮겨졌으면 옮겨진 행으로).
     닫히는 사이 사용자가 다른 요소를 누르면 그 요소에 포커스가 남는다. 다이얼로그 안에서 글을 고르다 배경에서 떼도 닫히지 않는다.
     툴팁은 :focus-visible 일 때만 포커스로 열리고, 기준이 사라지면 닫힌다(DESIGN 3.5절).
     메뉴는 마우스로 연 뒤 포커스를 강제로 주지 않고 Esc 를 누른다(WebKit은 클릭한 버튼에 포커스를 주지 않는다).
   - 키보드만으로: 사용자 만들기, 홈에서 보내기, Esc 로 멈추기, 행 메뉴로 이름 바꾸기와 고정과 삭제, 사용자 메뉴로 사용자 바꾸기를 Tab, Enter, 방향키, Esc 로만 한다.
   - 읽기: 메시지 스크롤 영역에 이름이 있고 Tab 으로 닿는다. 답변 중 aria-busy 가 true, 끝나면 false. live region 은 한 번 바뀐다.
   - 대비: 홈, 채팅(답변이 있는), 사용자 고르기, 메뉴를 연 상태에서 글자와 그 뒤 배경의 대비를 재 가장 낮은 값을 보고한다.
     두 테마 모두 글자 4.5:1, 테두리와 아이콘 3:1 이상이다(STYLE-7).
   - 동작 줄이기: reducedMotion reduce 에서 답변 대기 표시, 스켈레톤, 스피너, 토스트의 애니메이션이 멈춘다.
   돌려서 실패하는 출력을 보인다.
2. 구현
   - components/shell/shortcuts.ts: 단축키 목록 하나(키, 이름, 동작). 처리기, 툴팁, 도움말(shortcut-help.tsx)이 읽는다.
   - 열린 다이얼로그나 메뉴를 묻는 함수는 shell 에 하나만 둔다(COMP-5). 단축키마다 따로 막지 않는다.
   - 포커스 되돌리기는 ui 의 dialog 와 menu 가 맡고, 연 곳이 사라진 경우의 h1 은 화면의 ref 로 잡는다.
   - 대비가 모자란 곳은 tokens.css 의 값만 고친다(STYLE-6). 고친 토큰과 전후 대비를 보고한다.
3. 확인: bun run check(check:css 포함), @a11y e2e 를 세 엔진에서, bun run test:e2e.
4. docs/test-plan.md 의 직접 확인 목록에 이 단계의 직접 확인 세 가지를 더한다.
5. 작게 커밋한다.
```

## 막히면

- **Mac의 ⌘를 Windows에서 볼 수 없다.** 플랫폼 판별을 흉내 낸 테스트(`navigator.platform`을 `MacIntel`로)로 세 엔진에서 본다. 실제 Mac은 직접 확인 목록에 "확인하지 못함"으로 둔다.
- **`⌘/`가 실제 Safari에서 브라우저 기능과 겹칠 수 있다.** 실제 Safari가 없으면 "확인 못 함"으로 기록한다.
