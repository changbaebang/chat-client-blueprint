# 단계 상태

진행 방식: 기본

진행 방식은 기본, 빠른 모드, 가벼운 주기 중 사람이 고른다([DESIGN 10.5절](DESIGN.md#105-브랜치와-커밋)). 에이전트는 이 줄을 따른다.

**안정 기준(AGENTS.md 14장):** `main`은 언제든 내보낼 수 있어야 한다. 항목(결정과 이유가 문서에 있다), 반영(합류 전 실행이 통과했다), 마일스톤(세 엔진 전체가 통과했다. 첫 마일스톤은 17단계) 세 단위로 본다. `main`의 이 표에 "진행"은 없다. 명세만 합쳐지고 구현 전인 항목은 "명세"로 둔다.

상태는 대기, 진행, 명세, 반영, 안 함이다.

## 나중에 볼 것

단계를 하다 찾은 것 중 그 단계에서 고치지 않은 것이다. 처리하면 이 목록에서 지우고 처리한 곳을 적는다.

| 찾은 단계 | 무엇 | 언제 |
| --------- | ---- | ---- |
| 02 | `tsconfig.json` 하나에 DOM과 node 타입이 함께 있어, `src`에서 `process`나 `Buffer`를 써도 tsc가 잡지 않는다 | 03~04단계에서 화면 코드가 생길 때 |
| 02 | `check:css`는 `white`, `black` 같은 색 이름을 잡지 않는다. DESIGN 9.13절이 정한 범위의 빈틈이다 | 04단계 전에 넣을지 정한다 |
| 02 | 00단계 문서는 Bun을 winget으로 설치한다고 가정하지만, 이 PC의 Bun은 npm 전역 설치였다. npm 설치는 Node에 기대므로 "Git만 설치된 PC"라는 전제와도 다르다 | 00단계 "막히면"에 더할 것. 블루프린트 문서라 `docs/…` 브랜치에서 따로 고친다 |
