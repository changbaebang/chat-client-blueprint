# 결정 기록

[DESIGN 15장](DESIGN.md#15-결정-기록)의 표를 ADR 하나씩 펼친 것이다. 형식은 career-radar의 ADR이다. 결정을 바꾸면 DESIGN 15장과 이 문서를 같은 커밋에서 고친다.

항목은 상태, 맥락, 결정, 결과, 대안이다. 결정이 실제 환경에서 맞는지 단계에서 확인했으면 "확인(날짜, 단계)" 항목을 끝에 더한다. 확인은 결정을 바꾸지 않는 측정 기록이고, 잰 값의 표는 `docs/test-plan.md`에 둔다.

## ADR-001: 패키지 하나

- **상태:** 채택
- **맥락:** 웹(`src`), API 서버(`server`), 둘이 함께 쓰는 계약(`shared`)을 한 저장소에 둔다([DESIGN 8장](DESIGN.md#8-폴더-구조)).
- **결정:** 워크스페이스 없이 패키지 하나로 만든다.
- **결과:** 도구와 설정이 하나로 끝난다. 웹이 서버 코드를 가져오지 않는 경계는 설치 단계가 아니라 `check:imports`가 본다(EDGE-1).
- **대안:** 워크스페이스(웹, 서버, 계약을 따로). 웹이 서버 의존성을 가져오는 것을 설치 단계에서 막지만, 도구와 설정이 늘어난다.

## ADR-002: Bun 1.4 하나로 설치, 실행, 테스트

- **상태:** 채택
- **맥락:** Git만 설치된 Windows PC에서 시작한다([DESIGN 2장](DESIGN.md#2-기술-선택)).
- **결정:** 설치, 스크립트, TypeScript 실행, 모듈 테스트를 Bun 1.4로 한다.
- **결과:** Node를 따로 설치하지 않는다. 스크립트 안의 환경 변수와 작은따옴표가 Windows에서 설정 없이 된다(루트 `TASKS.md` 3.2절).
- **대안:** Node와 pnpm, tsx, Vitest. 처음 판의 선택이었다. 잰 결과 pnpm 12는 Windows에서 설정 두 가지가 더 필요했다. Bun으로 이 PC에서 모든 층을 돌려 봤다.
- **확인(2026-11-19, 02단계):** 이 PC의 Bun은 1.4.2다(`packageManager`는 `bun@1.4.4`). `bun install`이 의존성 열 개를 설치하고 종료 코드 0이었다. 막힌 lifecycle 스크립트는 없었다. `bun test`, Playwright(Chromium), `vite build`가 모두 Bun으로 돌았다.

## ADR-003: TypeScript 7.0.2

- **상태:** 채택
- **맥락:** 린터를 쓰지 않는다([DESIGN 2.3절](DESIGN.md#23-쓰지-않는-것)).
- **결정:** TypeScript 7.0.2를 정확히 고정해 쓴다.
- **결과:** typescript-eslint의 peer 범위(`<6.1.0`)에 묶이지 않는다.
- **대안:** 6.0. typescript-eslint를 쓸 때만 필요했다.
- **확인(2026-11-19, 02단계):** 설치된 `tsc`는 7.0.2다. 02단계의 `tsconfig.json` 옵션 그대로 `tsc --noEmit`이 고칠 것 없이 통과했다.

## ADR-004: 사용자와 목록은 RDB, 채팅 내용은 문서 저장소

- **상태:** 채택
- **맥락:** 이 앱이 보이려는 것은 RDB와 문서 저장소를 나눠 쓰는 데이터 설계다([DESIGN 5.1절](DESIGN.md#51-어디에-무엇을-두는가)).
- **결정:** 사용자와 채팅 목록은 SQLite(`node:sqlite`)에, 채팅 내용은 채팅마다 JSON 문서 하나에 둔다.
- **결과:** 두 저장소 사이의 쓰기 순서와 어긋났을 때 맞추는 법이 필요하다([DESIGN 5.4절](DESIGN.md#54-연산별-쓰기-순서), [5.5절](DESIGN.md#55-어긋났을-때-맞추기)).
- **대안:** 하나로 하기. 이유는 [DESIGN 5.6절](DESIGN.md#56-왜-하나로-하지-않는가)이다.

## ADR-005: 답변은 끝날 때 한 번 쓴다

- **상태:** 채택
- **맥락:** 답변은 조각으로 스트리밍된다([DESIGN 6.2절](DESIGN.md#62-답변-하나의-흐름)).
- **결정:** 답변 도중에는 문서에 쓰지 않고, 끝날 때 한 번 쓴다.
- **결과:** 쓰기가 답변 길이만큼 늘지 않고, 문서 잠금을 다투지 않는다. 서버가 도중에 죽으면 그 답변은 시작할 때 복구가 정리한다(DESIGN 5.5절).
- **대안:** 1초마다 쓰기. 죽어도 글이 남지만 쓰기가 답변 길이만큼 늘고, 그동안 문서 잠금을 다툰다.

## ADR-006: 문서 저장소를 직접 만든다

- **상태:** 채택
- **맥락:** 문서마다 잠금과 원자적 쓰기를 직접 보이는 것이 목적이다([DESIGN 5.3절](DESIGN.md#53-문서-형태), [5.7절](DESIGN.md#57-windows와-파일-저장)).
- **결정:** 채팅마다 JSON 파일 하나를 쓰는 저장소를 직접 만든다.
- **결과:** 임시 파일, `sync`, 이름 바꾸기, Windows의 `EPERM` 다시 시도를 코드로 보인다(DOC-2, DOC-3).
- **대안:** lowdb. 파일 하나에 모두 담는다.

## ADR-007: 로그인 없이 사용자를 고르고, 그 id를 `X-User-Id` 머리로 보낸다(프로토타입)

- **상태:** 채택
- **맥락:** 이 포트폴리오가 보이려는 것은 RDB와 문서 저장소의 나눔이다(2026-11-18 사용자 결정, 루트 `TASKS.md` D3).
- **결정:** 로그인 없이 사용자를 고르거나 만들고, 그 id를 요청 머리 `X-User-Id`로 보낸다.
- **결과:** 사용자 표와 소유권은 그대로 두어 나중에 로그인을 붙일 자리를 남긴다. 인증이 없다는 것은 받아들인 한계다([DESIGN 13장](DESIGN.md#13-보안)).
- **대안:** 이메일과 비밀번호, 쿠키 세션(처음 판). 비밀번호 해시, 세션 표, 실패 제한, CSRF까지 보안 코드가 커지는데, 보이려는 것에 보태는 것이 없다. JWT도 같은 이유다.

## ADR-008: 명시적 취소 API

- **상태:** 채택
- **맥락:** 사용자가 답변을 멈추고 바로 다시 보낼 수 있어야 한다(F-STOP-3).
- **결정:** 답변을 멈추는 취소 API를 둔다.
- **결과:** 취소는 잠금이 풀린 뒤 응답하므로, 멈춘 직후의 전송이 409가 되지 않는다(DOM-8).
- **대안:** 연결 끊기만. 잠금이 풀리기 전에 다음 전송이 오면 409가 난다.

## ADR-009: API를 Vite 플러그인으로 붙인다

- **상태:** 채택
- **맥락:** 개발 서버와 e2e 서버를 단순하게 두고 싶다([DESIGN 2.2절](DESIGN.md#22-의존성과-스크립트), [11.4절](DESIGN.md#114-e2e-서버와-데이터)).
- **결정:** API 처리기를 Vite 플러그인(`configureServer`, `configurePreviewServer`)으로 붙인다.
- **결과:** 프로세스 하나, 웹과 같은 출처라 프록시와 CORS가 없다.
- **대안:** 독립 서버와 프록시. 개발 중 프로세스가 둘, e2e 서버가 워커마다 둘이 된다.

## ADR-010: camelCase 필드, ISO 8601 UTC 시각

- **상태:** 채택
- **맥락:** 계약 타입 하나를 서버와 웹이 그대로 쓴다([DESIGN 4.1절](DESIGN.md#41-공통-규칙)).
- **결정:** JSON 필드는 camelCase, 시각은 ISO 8601 UTC 문자열이다.
- **결과:** 변환 층이 없다. 모든 브라우저 엔진이 같은 시각으로 읽는다.
- **대안:** snake_case는 변환 층이 생긴다. 비표준 시각은 엔진마다 다르게 읽힌다.

## ADR-011: 라우터, 데이터 패칭, 서버 프레임워크, 검증 라이브러리를 쓰지 않는다

- **상태:** 채택
- **맥락:** 화면 넷, 경로 열 개 남짓, 본문 여덟 개 규모다.
- **결정:** 라우터, 검증, HTTP 처리를 직접 만든다.
- **결과:** 의존성이 열 개에서 늘지 않는다(ADR-015).
- **대안:** react-router, TanStack Query, Express, Zod. 이 규모에서는 가져오는 비용이 더 크다.

## ADR-012: Markdown 렌더러를 직접 쓴다

- **상태:** 채택
- **맥락:** 답변은 Markdown이고 조각으로 와서, 그리는 도중의 글이 늘 불완전하다.
- **결정:** 답변에 쓰는 문법만 그리는 렌더러를 직접 쓴다.
- **결과:** 그리는 도중의 불완전한 글에서 무한 루프가 없는지 모듈 테스트로 본다(LIB-8).
- **대안:** react-markdown과 remark-gfm. 의존성이 둘 는다.

## ADR-013: `bun test`와 Playwright, DOM 흉내 없음

- **상태:** 채택
- **맥락:** 테스트 층은 모듈, HTTP, 브라우저다([DESIGN 11.1절](DESIGN.md#111-층)).
- **결정:** 모듈과 HTTP는 `bun test`, 브라우저는 Playwright로 본다. DOM 흉내는 쓰지 않는다.
- **결과:** 테스트 도구를 더하지 않는다.
- **대안:** Vitest는 Bun에 내장된 것으로 충분하다. jsdom은 [DESIGN 2.3절](DESIGN.md#23-쓰지-않는-것)이다.

## ADR-014: e2e 전체는 개발 서버, 빌드는 preview로 스모크

- **상태:** 채택
- **맥락:** 렌더 횟수는 개발 모드에서만 셀 수 있다([DESIGN 11.4절](DESIGN.md#114-e2e-서버와-데이터)).
- **결정:** e2e 전체는 개발 서버에서, 빌드한 앱은 preview 서버에서 `@smoke`만 돈다.
- **결과:** 렌더 횟수와 빌드한 모양을 둘 다 본다.
- **대안:** 빌드만은 렌더 횟수를 볼 수 없고 매번 빌드해야 한다. 개발 서버만은 빌드한 모양을 보지 못한다.

## ADR-015: 의존성은 열 개

- **상태:** 채택
- **맥락:** 가볍게 간다(루트 `TASKS.md` D2).
- **결정:** 의존성은 [DESIGN 2.2절](DESIGN.md#22-의존성과-스크립트)의 열 개로 정확히 고정한다(`^` 없음). 더하려면 ADR을 남긴다.
- **결과:** 쓰지 않는 것과 이유는 DESIGN 2.3절의 표에 있다.
- **대안:** [DESIGN 2.3절](DESIGN.md#23-쓰지-않는-것)의 표.
- **확인(2026-11-19, 02단계):** `npm view`로 열 개 버전이 모두 있음을 봤고, 설치된 버전이 DESIGN 2.2절과 같다: react 19.3.1, react-dom 19.3.1, @fontsource-variable/geist 5.3.0, vite 8.3.8, @vitejs/plugin-react 6.3.0, typescript 7.0.2, @playwright/test 1.65.1, @types/node 26.6.6, @types/react 19.3.0, @types/react-dom 19.3.0.

## ADR-016: 서버는 Bun 전용 API를 쓰지 않는다

- **상태:** 채택
- **맥락:** 서버를 Node에서도 돌게 둔다(EDGE-2).
- **결정:** 서버와 스크립트는 `node:` 모듈만 쓴다.
- **결과:** `node:sqlite`가 Bun에서 경고 없이 돈다는 것을 쟀다(루트 `TASKS.md` 3.2절).
- **대안:** `Bun.serve`, `bun:sqlite`. 조금 빠르고 짧지만, 서버가 Bun에 묶인다.

## ADR-017: 폴더마다 `CLAUDE.md`를 두지 않는다

- **상태:** 채택
- **맥락:** 폴더별 규칙은 `POLICY.md`에 있다([DESIGN 9장](DESIGN.md#9-폴더별-정책)).
- **결정:** 루트의 `CLAUDE.md`가 `AGENTS.md`를 부르고, `AGENTS.md`가 "고치기 전에 그 폴더의 `POLICY.md`를 읽는다"고 말한다.
- **결과:** 규칙의 출처가 하나다. Claude와 다른 에이전트가 같은 문서를 읽는다.
- **대안:** 폴더별 `CLAUDE.md`(`@POLICY.md`). 그 폴더의 파일을 읽을 때만 불러오고 셸로 고칠 때는 불러오지 않는다. "작성 중" 초안도 똑같이 불러온다. Claude만 읽어 규칙의 출처가 둘이 되고, 늘 컨텍스트를 차지한다.

## ADR-018: 컴포넌트 테스트(RTL, happy-dom)를 두지 않는다

- **상태:** 채택
- **맥락:** 화면 e2e가 지키는 것은 거의 모두 브라우저에서만 보이는 동작(포커스, 배치, `:focus-visible`, 엔진 차이)이다.
- **결정:** 컴포넌트 테스트를 두지 않는다.
- **결과:** 그런 동작은 DOM 흉내로 옮길 수 없어 e2e가 맡는다.
- **대안:** RTL과 happy-dom. 쓰게 될 조건: 합류 전 Chromium 전체가 시간 예산([DESIGN 11.3절](DESIGN.md#113-실행-시점))을 넘고, 배치와 무관한 컴포넌트 동작이 많아질 때.
